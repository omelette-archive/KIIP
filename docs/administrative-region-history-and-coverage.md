# 행정구역 이력과 특산품 수집 누락 보완

기준 화면과 집계 키는 항상 최신 법정동코드의 한 지역명만 사용한다. 과거 명칭을 화면에
별도 지역으로 만들지 않고, 수집 원문에 남아 있는 과거명·과거 코드를 현재 지역으로 승계한다.

## 매칭 순서

1. 원천에 10자리(또는 5자리) 지역코드가 있으면 현재 법정동코드와 먼저 대조한다.
2. 폐지된 코드이며 목적지가 하나인 경우 `regionAliases.js`의 명시적 승계표를 적용한다.
3. 코드로 못 찾으면 현재명·축약명·과거명을 이름으로 대조한다.
4. 분할 뒤 목적지가 둘 이상이거나 동명 지역을 좁힐 근거가 없으면 자동 배분하지 않고
   `unresolved/ambiguous`로 남긴다.

현재 자동 승계하는 주요 이력은 다음과 같다.

| 과거 지역 | 현재 집계 지역 | 처리 |
|---|---|---|
| 충청남도 연기군 | 세종특별자치시 세종시 | 이름·코드 승계 |
| 제주도 북제주군 | 제주특별자치도 제주시 | 이름·코드 승계 |
| 제주도 남제주군 | 제주특별자치도 서귀포시 | 이름·코드 승계 |
| 경상북도 군위군 | 대구광역시 군위군 | 현재 이름/코드 우선, 과거 코드 승계 |
| 마산시·진해시 | 경상남도 창원시 | 이름·코드 승계 |
| 청원군 | 충청북도 청주시 | 이름·코드 승계 |

`제주도`처럼 도 전체만 적힌 자료는 제주특별자치도 도 단위로 남긴다. 제주시와 서귀포시 중
어느 곳인지 근거가 없으므로 임의 복제하지 않는다.

## 세종·제주 0건 감사 결과 (2026-08-21)

농사로 `localSpcprd`는 최신명뿐 아니라 다음 과거명으로 실조회해도 모두 0건이었다.

- 세종: 세종, 세종시, 세종특별자치시, 연기군
- 제주: 제주, 제주도, 제주특별자치도, 제주시, 서귀포시, 남제주군, 북제주군

따라서 이 두 지역은 행정구역 별칭만 추가해서 복구할 수 있는 문제가 아니며 농사로 소스 자체의
범위 공백이다. 공식 대체 출처에서 확인된 항목을 별도 sourceId로 보완했다.

| 지역 | 보완 출처 | 수집 품목 | 자동 정규화 |
|---|---|---:|---:|
| 세종특별자치시 세종시 | 세종시 읍면동 공식 `특산품` 페이지 | 7 | 6 |
| 제주특별자치도(도 일원) | 국립농산물품질관리원 지리적표시 등록 목록 | 3 | 2 |

세종은 복숭아·배·수박·딸기·오이·절임깻잎·포도, 제주는 한라봉·녹차·돼지고기를 확보했다.
브랜드성 원문(`싱싱세종수박`, `금강배`)은 `sourceItemName`에 보존하고 분석용 품목은 원물명으로
분리했다. `절임깻잎`과 `한라봉`은 고시상품명칭을 보수적으로 확정할 수 없어 ②단계 검토대기로
남는다.

## 재현·감사 필드

① 출력에는 기존 출처 필드 외에 다음을 보존한다.

- `regionCode`: 현재 기준 지역코드
- `regionMatchMethod`: 코드 완전일치, 과거 코드 승계, 이름 별칭 등의 적용 경로
- `sourceRegionName`, `sourceRegionCode`: 원천에 적힌 지역명과 코드
- `sourceItemName`: 공식 페이지에 표시된 원문 품목명
- `sourceRecordUrl`: 해당 원문을 다시 확인할 주소

이 필드는 ② 정규화와 ③ 상표검색 provenance까지 전달되므로, 나중에 현재 집계 결과에서 어떤
과거 표기가 승계됐는지 역추적할 수 있다.
