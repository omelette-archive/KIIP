# ⑦ 대시보드 지표·데이터 계약 초안

상태: `dashboard-data-contract-v0-draft`

최종 갱신: 2026-08-10

UI 아이디에이션 참고: <https://local-k-tm.pages.dev/>

이 문서는 대시보드 화면을 만들기 전에 각 숫자의 의미, 사용 가능한 데이터, 추가로 필요한 데이터,
출처·버전 표시 방법을 먼저 고정하기 위한 초안이다. 참고 사이트와 저장소의 정적 목업은 화면 구성의
참고일 뿐 데이터 출처나 업무 기준이 아니다.

## 1. 반드시 지킬 원칙

1. `데이터 없음`, `수집 완료 후 0건`, `부분 수집`, `오류`, `검토대기`를 서로 다른 상태로 표시한다.
2. 농사로 지역브랜드 연관 지역과 출원인 주소를 합치지 않는다.
3. 출원인 주소가 확인되기 전의 KIPRIS 검색 hit를 해당 지역 기업의 상표로 표현하지 않는다.
4. `collectionStatus=partial` 결과를 완전한 모집단처럼 합계·순위에 사용하지 않는다.
5. 예시 점수와 승인된 정책 기준을 구분하고 `scoreVersion`을 화면에 표시한다.
6. 모든 카드·지도·표는 기준일, 출처, 규칙 버전, 표본 범위를 역추적할 수 있어야 한다.
7. 샘플 실행은 항상 `sample` 배지를 표시하고 전국 통계·정책 결론으로 표현하지 않는다.

## 2. 화면 구성과 지표 정의

### 2.1 전체 현황

| 화면 지표 | 정의 | 현재 준비도 |
|---|---|---|
| 분석 지역 수 | ④ `regions` 중 검색 가능한 지역 수 | 사용 가능. 전체 행정구역 커버리지와는 별도 |
| 지역×품목 수 | ④ `regionItems` 수 | 사용 가능 |
| 고유 상표 수 | 출원번호 우선 키로 중복 제거한 ④ `summary.uniqueTrademarkCount` | 사용 가능 |
| 등록 상표 수 | ④ `statusCounts.registered` | 사용 가능 |
| 등록률 | `registered / uniqueTrademarkCount` | 사용 가능. 부분 수집 경고 필요 |
| 신규 출원 수 | 이전 스냅샷에 없고 현재 스냅샷에 처음 등장한 출원번호 수 | 추가 구현 필요 |
| 공백 경고 수 | ⑥ `summary.alertCount` | 미리보기만 가능. #29 기준 확정 필요 |
| 데이터 기준일 | 각 소스 수집시각과 ④~⑥ 생성시각 중 화면 지표에 실제 사용된 시점 | 사용 가능 |

### 2.2 지도

지도는 하나의 색에 여러 의미를 섞지 않고 사용자가 지표를 선택하게 한다.

| 지도 모드 | 색의 의미 | 사용 조건 |
|---|---|---|
| 데이터 커버리지 | 검색 완료 지역×품목 비율 | MVP 기본값 |
| 검색 연관 상표 | 해당 지역×품목 검색에 저장된 고유 hit | 현재 가능하나 지역 소유 상표로 표현 금지 |
| 등록률 | 저장 hit 중 등록 상태 비율 | 부분 수집 경고와 함께 제공 |
| 최근 증감 | 동일 기간 출원 건수 증감 | ④ 시계열 기준 사용 |
| 브랜드 공백 | ⑤ `gapScore` | #29 승인 전 `예시 기준` 배지 필수 |
| 지역 출원인 비중 | 주소가 해당 지역인 상표 비율 | #11 완료 전 비활성화 |

지도 범례에는 최소한 다음 상태가 따로 있어야 한다.

- `not_collected`: 아직 검색하지 않음
- `complete_zero`: 수집을 완료했으나 결과 0건
- `complete_nonzero`: 수집 완료, 결과 있음
- `partial`: 페이지·hit·요청 상한에 걸린 부분 수집
- `error`: API 오류
- `skipped`: ② 검토대기·제외 때문에 검색하지 않음

### 2.3 지역·품목 상세

- 원본 품목명, 표준 품목명, 고시명칭, NICE류
- 고유 상표 수, 등록률, 상태 분포, 연도별 추이
- 최근 상표명·출원번호·출원일·상태
- KIPRIS 키워드 전체 건수와 실제 저장 hit 건수의 분리 표시
- 지정상품 대조 결과: `exact|normalized|similar_group|class_only|unverified` (#12)
- 출원인 주소 판정: `inside|outside|unverified` (#11)
- 농사로 지역브랜드 판정: 별도 `regionalBrand*` 영역
- 원본 출처, 콘텐츠 ID, 계약 버전, 수집일, 분석 버전

### 2.4 브랜드 공백과 전략

- 순위, `gapScore`, 대표 특산품 판정 근거
- 점수 입력값과 가중치, `scoreVersion`, #29 승인 상태
- 부분 수집·결측이 점수에 미친 영향
- ⑥-1 고정 템플릿 원문과 사용한 evidence
- 향후 ⑥-2 AI 제안은 원문과 분리해 모델·프롬프트 버전·생성시각·승인상태 표시

### 2.5 신규 출원 모니터링

현재 ③ 결과는 실행별 JSON/체크포인트 중심이라 시점 간 변화를 안정적으로 조회하는 저장 계층이
없다. 다음 이벤트를 만들려면 상표 스냅샷 또는 이력 테이블이 필요하다.

- 처음 관측된 출원번호
- 출원 상태 변경
- 신규 등록 또는 소멸
- 지역×품목 최초 상표
- 이전 실행의 오류·부분 수집이 해소된 경우

`새로 관측됨`과 `실제 신규 출원`을 구분한다. 최초 전체 적재에서 발견된 과거 상표를 신규 출원
알림으로 보내면 안 된다.

## 3. 대시보드 통합 스냅샷 계약

⑦은 ④·⑤·⑥ JSON을 브라우저에서 각각 직접 조합하지 않는다. 별도 어댑터가 다음 형태의 읽기 전용
`dashboard-snapshot.json` 또는 동일 구조의 조회 테이블을 만든다.

```text
{
  schemaVersion: "dashboard-snapshot-v1",
  snapshotId,
  generatedAt,
  mode: "sample" | "full",
  asOf,
  versions: {
    analysisVersion,
    scoreVersion,
    templateVersion,
    dashboardContractVersion,
    geographyVersion
  },
  coverage: {
    targetRegionCount,
    observedRegionCount,
    regionItemCount,
    completeQueryCount,
    partialQueryCount,
    errorQueryCount,
    skippedQueryCount
  },
  sources: [],
  warnings: [],
  regions: [
    {
      regionCode,
      sido,
      sigungu,
      dataState,
      metrics: {},
      items: []
    }
  ],
  rankings: [],
  briefings: [],
  alerts: []
}
```

### 3.1 결합 키

- 지역: 화면 표시명이 아니라 현재 기준 행정구역 코드
- 품목: 내부 `specialtyId`와 ②의 고시명칭·NICE류 조합
- 상표: 정규화된 `applicationNumber`, 없으면 `registrationNumber`
- 분석 스냅샷: `snapshotId + regionCode + specialtyId`

현재 단계에는 안정적인 `specialtyId`가 없으므로 스냅샷 어댑터 구현 전에 추가해야 한다. 이름만
키로 쓰면 표준화 규칙이나 행정구역 명칭 변경 때 과거 시계열이 끊긴다.

### 3.2 각 지표 공통 메타데이터

중요 지표는 값만 저장하지 않고 다음 정보를 함께 제공한다.

```text
{
  value,
  availability: "available" | "preview" | "blocked",
  status: "complete" | "partial" | "error" | "not_collected",
  sourceIds: [],
  calculatedAt,
  methodVersion,
  rationale,
  blockingIssue
}
```

## 4. 필요한 저장 구조

| 엔터티 | 목적 | 주요 필드 |
|---|---|---|
| `region_dim` | 지도·행정구역 변경 관리 | 지역코드, 상하위코드, 현재명, 별칭, 유효기간, 경계 버전 |
| `specialty_dim` | 품목의 안정 ID | 원문·표준명·고시명칭·NICE류·규칙 버전 |
| `region_specialty` | 지역과 품목의 다대다 근거 | sourceId, sourceRecordId, 유효기간, 검토상태 |
| `trademark_fact` | 상표 원문과 상태 이력 | 출원·등록번호, 상태·날짜, 지정상품, 출원인 |
| `trademark_relation` | 검색/지정상품/지역 관계 | matchMethod, confidence, evidence, queryStatus |
| `analysis_snapshot` | 시점별 ④ 집계 | snapshotId, 지역·품목 키, 지표, 분석 버전 |
| `gap_snapshot` | 시점별 ⑤ 결과 | 점수, 입력값, 가중치, 기준 버전 |
| `strategy_review` | ⑥ 원문·AI 제안·사람 승인 | 원본 참조, 제안 버전, 승인상태, 감사 필드 |
| `collection_health` | 운영 상태 | 실행 ID, 소스, 성공·오류, 요청 수, 최신 수집시각 |

## 6. 지도 경계 데이터

현재 목업은 `southkorea-maps`의 2013년 KOSTAT 경계를 사용하고 표시명만 현재 파이프라인 명칭으로
보정한다. 실제 서비스에서는 다음을 충족하는 별도 버전 관리가 필요하다.

- 현재 행정구역 코드와 경계가 일치하는 공식 또는 이용허락 가능한 GeoJSON
- `geographyVersion`, 제공기관, 원본 URL, 다운로드일
- 폐지·통합·명칭 변경 지역의 과거 코드 매핑
- 지도 경계와 분석 데이터의 코드 불일치 검증

경계가 오래됐다는 사실을 이름 치환으로 숨기지 않는다.

## 7. 선택적 확장 데이터

상표 공백과 시장성을 함께 보여주려면 아래 자료가 추가로 필요하다. MVP에는 넣지 않고 각 값의
공식 출처와 갱신 주기를 확보한 뒤 별도 지표로 추가한다.

- 생산량·출하량·매출·수출
- 사업체 수·인구·관광객
- 지자체 브랜드 사업·지원 예산
- 검색량·뉴스·온라인 언급량

상표가 적다는 사실과 시장성이 높다는 판단은 서로 다른 근거이므로 하나의 점수로 자동 합치지 않는다.

### 7.1 참고 화면에서 확인한 데이터 후보

아래 항목은 참고 사이트가 보여주는 화면을 우리 출력과 대조해 얻은 후보이며, 참고 사이트 자체를
공식 근거로 사용하지 않는다. 실제 도입 전 담당 기관의 원본·기준일·이용조건을 별도로 확인한다.

| 후보 | 현재 상태 | 필요한 조치 |
|---|---|---|
| 정책 지정 특화작목 | 농사로 지역특산물과 별개일 가능성 | 농촌진흥청 등 공식 지정 목록과 버전 확인 |
| 품목별 GI 등록 현황 | ① 원본은 있으나 ④ 품목 집계 없음 | 안정적인 품목 키로 GI를 조인해 별도 지표 생성 |
| 광역자치단체 비교 | 시군구 결과 중심 | 현재 행정구역 코드로 시도 롤업 추가 |
| 품목별 대표 출원지역 | 지역×품목 결과만 있음 | 품목 기준 재그룹과 지역 TOP N 집계 추가 |
| 원물·가공품·서비스 단계 | 분류 규칙 없음 | NICE류·지정상품 근거의 단계 매핑 규칙 승인 필요 |
| 범용 품목 제외 | 규칙 없음 | 제외어·근거·버전을 갖춘 검토 규칙 필요 |

특히 현재 ②에서 제외 후보로 다루는 NICE 35류 이상을 서비스 확장 분석에 사용할지는 서로 다른
정책 선택이다. 기존 수집 결과를 조용히 재해석하지 말고, 분석 목적과 포함 범위를 별도 버전으로
승인한 뒤 구현한다.

## 8. 구현 순서와 완료 조건

1. 지표 정의와 상태 표현을 검토·승인한다.
2. 안정적인 `regionCode`·`specialtyId`를 추가한다.
3. ④·⑤·⑥을 결합하는 스냅샷 어댑터와 고정 fixture를 만든다.
4. 샘플 모드로 지도·상세·근거 패널을 구현한다.
5. #11·#12 결과가 들어오면 비활성 지표를 단계적으로 연다.
6. 상표 스냅샷 이력을 저장한 뒤 신규 출원 알림을 구현한다.

완료된 대시보드는 다음 조건을 만족해야 한다.

- 0건과 미수집이 시각적으로 다르다.
- 모든 지도 색과 KPI의 계산 정의를 화면에서 확인할 수 있다.
- sample/partial/preview 상태가 숨겨지지 않는다.
- 표시된 숫자에서 원본 출처·버전·기준일로 이동할 수 있다.
- 지역브랜드 연관성과 출원인 주소가 별도 지표다.
- AI 제안이 결정론적 원문과 구분되고 승인 전 자동 반영되지 않는다.
