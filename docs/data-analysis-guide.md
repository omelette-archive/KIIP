# 현재 분석 워크플로

이 문서는 KIIP가 현재 데이터를 어떻게 수집·판정·공개하는지 설명하는 기준 문서다. 과거 실행
수치와 이슈별 조사 과정은 날짜가 붙은 감사·인계 문서에 남기고, 여기에는 계속 유지할 흐름과
판정 경계만 둔다.

## 1. 공식 목록을 출처 범위 그대로 수집한다

지역 특산품의 출발점은 생성형 AI가 아니라 출처가 확인되는 공식 목록이다.

- 농사로 지역특산물, 농산물·수산물 지리적표시, 지자체 공식 페이지
- 농촌진흥청 2025 지역특화작목 69개(9개 도의 대표·집중육성·자체육성 작목)
- 품질인증수산물·임산물 품목 등 전국 단위 보완 카탈로그
- 법정동 코드와 원문 지역명

각 행은 `sourceId`, 계약 버전, 수집 시각, 원문 지역과 정규화 지역을 보존한다. 도 단위 정책
목록은 도 단위로만 쓰고 시군구로 추정하지 않는다. 지역 필드가 없는 전국 카탈로그도 지역
특산품 근거로 바로 편입하지 않는다.

## 2. 원문 품목을 검색 가능한 기준으로 정규화한다

원문 품목명을 고시상품명칭과 NICE류에 대조하고 판정 경로를 남긴다.

| 판정 | 처리 |
|---|---|
| 완전 일치 | 자동 확정 |
| 사람이 승인한 반복 별칭 | 승인 사전으로 확정 |
| 결정론적 규칙 | 규칙 버전과 근거를 남겨 확정 |
| 애매함·사전 공백 | `review_required`로 보류 |

품목명에 업체명·브랜드명·가공 상태가 섞인 경우에는 억지로 원물명으로 확정하지 않는다.
생성형 AI의 제안은 검토 보조일 뿐 자동 승인 근거가 아니다.

## 3. 상표 후보와 근거를 두 경로로 보강한다

KIPRIS 단어검색은 전국 후보를 찾는 단계다. 검색 건수만으로 지역 상표 활동을 만들지 않는다.

### 경로 A — 출원번호와 출원인 주소

출원번호 기반 출원인 정보에서 주소를 정규화해 `inside`, `outside`, `unverified`로 판정한다.
지역 지표에는 주소가 해당 지역으로 확인된 후보만 반영한다.

### 경로 B — 등록번호와 등록원부

등록번호가 있는 후보는 등록원부에서 권리자·주소·지정상품·권리 상태를 보강한다. 지정상품은
정규화 완전일치와 포함일치를 구분하고, 상품류만 같은 경우는 확정 근거로 쓰지 않는다.

등록원부 수집은 장기 실행을 전제로 한다.

- 성공 응답과 미완료 상태를 캐시·체크포인트에 저장한다.
- 일일 호출 예산과 429 회로차단의 재개 시각을 지킨다.
- 공식 권리존속기간 만료예정일이 지난 캐시는 재검증 대상으로 선별한다.
- 신규 등록번호는 증분 수집하고, 만료예정일로 잡히지 않는 이전등록 등 변경은 후속 범위로
  명시한다.

즉, 등록원부 대조율은 고정 완료값이 아니라 근거가 누적되는 운영 상태다. 상세 절차는
[`applicant-region-recovery-runbook.md`](applicant-region-recovery-runbook.md)를 따른다.

## 4. 지역 분석과 전국 사업흐름을 분리한다

### 지역 브랜드 활동·공백

지역×품목 버킷은 지역 귀속 근거가 있는 출원만 집계한다. 검색이나 주소 보강이 불완전하면
`availability`, `warnings`, `blockingIssue`로 제한을 노출하고 점수·순위를 차단한다.

`regionalMetricAvailability`는 세 상태다. `available`은 수집이 완료된 확정치, `blocked`은
오류·미수집으로 지역 수치를 못 내는 상태다. `partial`(#116, 2026-09-01)은 흔한 작물명처럼
전국 단어검색이 상한에만 걸렸고 오류·건너뜀은 없는 경우로, 출원인 주소가 `inside`로 검증된
고유 출원 수(상한과 무관하게 확정)를 최소 확인값으로 노출한다 — 화면에서 건수에 `+`를
붙이고 "더 있을 수 있음"을 안내한다. `regionalMetricGate.partialRegionItemCount`로 별도 집계한다.

대표 특산품 기준은 다음 중 하나다.

1. 지리적표시 등록 품목
2. 지역 귀속이 확인된 상표 출원 1건 이상

대표 품목에만 상표 활동량과 등록률을 이용한 공백 점수를 계산한다. 현재 활동량 포화값과
가중치는 확정 정책값이 아니므로 `scoreVersion`으로 구분한다. 전국 검색 건수와 미검증 주소는
대표성·공백 점수에 넣지 않는다.

### 전국 사업 확장

전국 176개 품목의 KIPRIS 후보를 다음 단계로 분류한다.

- `raw`: 원물 중심 상품류·지정상품
- `processed`: 가공식품·파생 상품
- `service`: 유통·판매·외식 등 서비스
- `excluded` 또는 미확정: 품목과 무관하거나 근거가 부족한 후보

현재 단계 분류는 NICE류와 상표명 안의 가공 지표 단어를 이용한 결정론적 근사다. 등록원부
지정상품 대조가 완료된 후보는 검증 근거를 강화하지만, 대조되지 않은 후보를 확정 분류로
표현하지 않는다.

단계별 건수, 주요 출원인, 출원인 지역 군집을 비교해 생산지와 사업 주도 지역의 차이 및
가공·서비스 확장 여지를 찾는다. 전국 흐름은 전략 참고 정보이며 지역 상표 건수, 지역 대표성,
지역 공백 점수와 합산하지 않는다.

## 5. 전략 후보와 대시보드를 만든다

전략 단계는 지역 공백 근거와 전국 단계별 흐름을 함께 보여주되 둘의 단위를 명확히 표시한다.
고정 규칙으로 만든 초안과 데이터 근거를 우선하고, 생성형 AI 문구는 별도 검토 없이 정책 결론
또는 자동 확정값으로 취급하지 않는다.

대시보드 스냅샷은 다음을 함께 제공한다.

- 지역 지도·지자체·품목별 출원 및 등록 근거
- 농촌진흥청 지정 특화작목과 실제 주소 일치 출원 비교
- 품목별 전국 원물→가공품→서비스 흐름
- 수집 모드, 출처, 방법 버전, 가용성, 경고와 차단 사유

공개 전 감사는 전국 후보가 지역 통계에 섞이지 않았는지, 지정상품 근거와 출처 계약이
유지되는지 검사한다.

## 현재 남은 운영 과제

- 등록원부 지정상품·권리 상태의 증분 보강과 변경 감지 범위 확대
- 검토 대기 품목과 원물/가공품 경계의 승인 사전 확장
- 소스별 지역 커버리지 차이를 보완하되 전국 자료를 지역 근거로 오용하지 않는 결합 규칙
- 공백 점수의 활동량 포화값·가중치에 대한 정책 기준 확정
- 전국 사업흐름 분류의 정확도와 서비스 단계 정의 검증

## 재현과 검증

```bash
node scripts/runOperationalPipeline.js --dry-run --run-id YYYYMMDD-manual
node scripts/validatePipeline.js
node scripts/auditDashboardSnapshot.js
```

입출력 필드는 [`data-pipeline-contracts.md`](data-pipeline-contracts.md), 출처 근거는
[`data-source-provenance.md`](data-source-provenance.md), 공개 스냅샷 규칙은
[`dashboard-data-contract.md`](dashboard-data-contract.md)를 기준으로 한다.
