# 고시상품명칭 데이터

지식재산처(KIPO)가 공개 배포하는 NICE 13판(2026) 고시상품명칭 목록. API 키/가입 없이
다운로드 가능. 출처: `https://kipo.go.kr/ko/kpoContentView.do?menuCd=SCD0201120`
(파일: `지식재산처 고시상품명칭 13판(2026).xlsx`, 다운로드 2026-08-05).

## 파일

- `고시상품명칭_13판_2026.xlsx` — 원본. 시트 7개: 메인 시트 + 35류(도매업/소매업/중개업/
  판매대행업/판매알선업/구매대행업) 파생 시트 6개. 35류 시트는 메인 시트 품목명에 업종
  접미사를 붙인 파생 데이터라 지금은 CSV로 변환하지 않음 — 35류 처리가 필요해지면 원본
  xlsx에서 다시 뽑는다.
- `고시상품명칭_13판_2026.csv` — 메인 시트(`26년 지정상품 고시목록(출처미포함)`)만 CSV로
  변환. 57,703행, UTF-8 BOM.

## 컬럼

| 컬럼 | 설명 | 예 |
|---|---|---|
| 지정상품(국문) | 고시상품명칭(국문) | 붕소비료 |
| NICE분류 | NICE 상품분류 코드 (2자리, 01~45) | 01 |
| 유사군코드 | 유사군코드 | G0101 |
| 지정상품(영문) | 고시상품명칭(영문) | boron fertilizers |

## 용도

`02-normalize-items`의 "품목 → 고시명칭 자동 매핑" + "NICE 상품분류 자동 매핑"에 쓰는
사전(vocabulary) 데이터. tksm 품목명을 이 사전과 대조/임베딩 매칭해서 가장 가까운
고시명칭·NICE분류·유사군코드를 붙이는 방식을 검토 중.

# 품목 유형 분류 데이터 (`item-categories-v1.json`)

이슈 #109(품목 카테고리화 요청)에 대응해 만든, 확정 특산품 고시명칭(2026-08-24 기준
291개) → 유형(과일/채소/곡물 등) 매핑.

## 왜 룰 기반 사전인가

농사로 `localSpcprd` API 실응답을 직접 확인한 결과 유형 필드가 없다(`areaCode`,
`cntntsSj`, `areaNm`, `imgUrl`, `svcDt`, `linkUrl`만 존재). 자동으로 뽑아 쓸 소스가 없어
사람이 직접 유형화했다. 생성형 AI가 특산품 데이터를 직접 판정하지 않는다는 기존 원칙
(이슈 #16)에 맞춰, 결과를 결정론적 정적 조회 테이블(이 파일)로 관리한다 — 매 실행마다
같은 입력에 같은 유형이 나온다.

## 구조

- `categories`: 유형 코드 → 한글 라벨 12종(`grain`/`vegetable`/`fruit`/`special_crop`/
  `forest_product`/`livestock`/`seafood`/`processed_food`/`beverage_alcohol`/
  `flower_plant`/`craft`/`other`)
- `items`: 고시명칭(접두어 "신선한 "/"미가공 " 제거된 표시명 기준, `Dashboard.tsx`의
  `officialItemLabel()`과 동일 규칙) → 유형 코드
- `reviewRequired`: 분류가 모호해 최선 추정으로 남긴 항목(잔디, 천일염, 칠보석, 허굴농차,
  황토소금) — 후속 확인 대상

## 갱신 방법

새 고시명칭이 추가되면 이 파일에 항목을 더한다. 아직 자동 검증 스크립트는 없다 — 추가할
때 `dashboard-snapshot.json`의 확인 특산품(고시명칭) 목록과 대조해 누락이 없는지 확인
필요.

# 임산물DB백과 참고 사전 (`kofpi-forest-products-v1.json`)

이슈 #114(수집경로 추가 검토)에서 조사한 한국임업진흥원 임산물DB백과(인증 불필요
공개 API)를 2026-08-25에 전량 조회해 저장한 스냅샷. 대분류 8종(수실류/버섯류/
산나물류/약초류/수엽류/약용류/수목부산물류/관상산림식물류) 아래 소분류 품목
90개와 각 품목의 학명·영문명·과명을 담는다.

## 왜 "수집 소스"가 아니라 "참고 사전"인가

이 API는 품목 사전이지 지역 데이터가 아니다 — 어느 시/군에서 나는지 정보가 없다.
그래서 01단계(수집)에 새 지역×품목 행을 만드는 소스로 쓰지 않고, 02단계
(`lib/ruleNormalizer.js`)에서 고시명칭 사전에 정확히 일치하는 후보가 없는
원물명(`review_required`)이 실제로는 알려진 임산물일 때(예: "고성오대미"가
"오대"+"미" 조합이듯, "장흥표고"가 "표고"를 포함) 검토 사유에 학명·과명을
덧붙이는 참고 근거로만 쓴다 — 자동으로 `status: "ok"`로 확정하지 않는다
(고시명칭 사전과 이 사전은 서로 다른 목적의 별개 사전이라, 자동 확정하면
검증되지 않은 명칭 승격이 된다).

## 재생성 방법

정적 스냅샷이라 파이프라인 실행 중에는 API를 호출하지 않는다. 원본 API가
바뀌었거나 갱신하려면 대분류(`selBClass.do`) → 소분류(`selMClass.do?bc_cd=`)
→ 상세(`selDinfo.do?bc_cd=&mc_cd=`) 순서로 다시 받아야 한다. **주의**: 이
API 서버는 실제로 EUC-KR 바이트를 보내는데, Node 내장 `fetch`(undici)로
호출하면 한글이 리터럴 "?"로 깨진다(원인 미상, 직접 확인함) — `curl`로 우회해
받은 뒤 `TextDecoder("euc-kr")`로 디코딩해야 한다. 일반 브라우저 User-Agent
헤더도 필수다(없으면 보안정책 차단 메시지가 빈 200 응답으로 옴).
